Adoption model

Five adoption levels

1 · AnswerPromptingA human asks and evaluates each response.
2 · EditAssisted codingThe model prepares a bounded change.
3 · TaskAgentic codingThe agent explores, changes, tests, and corrects.
4 · ContractSpec drivenAcceptance criteria control the work.
5 · ProcessBounded autonomyThe agent handles a recurring workflow inside limits.
This is a workshop model, not an industry standard.

Risk-adjusted adoption

Maturity means a repeatable control system, not access to a stronger model.

Prompting

Goal, Context, Boundaries, Evidence

GGoalWhat observable outcome should exist?
CContextWhich files, commands, and facts matter?
BBoundariesWhat may change, what may not, and when should it ask?
EEvidenceWhich checks prove completion?
Goal: make the production deployment gate reject destructive plans.
Context: task.md, src/deploy-gate.mjs, existing tests.
Boundaries: preserve the API; no new dependency; stop before deploy.
Evidence: focused tests pass; show the diff and remaining risks.

Project guidance

Global facts, local rules

repo/
├── CLAUDE.md                 # build, architecture, shared invariants
├── .claude/rules/terraform.md # paths: infra/**/*.tf
├── .claude/rules/k8s.md       # paths: deploy/**/*.yaml
├── services/api/CLAUDE.md     # service-local facts
└── CLAUDE.local.md            # personal, not committed

Write rules for surprises.
Do not restate what the code or formatter already makes obvious.

Use observable language.
Name the command, path, invariant, or review evidence.

Resolve conflicts.
Claude loads files additively. More text does not create stronger enforcement.

demos/02-rules-scope

Deterministic boundary

Sensitive files need a runtime boundary

1 · Remove accessDo not mount secrets into the workspaceContainer, ephemeral credentials, separate identity, or redacted fixtures.
2 · Deny file toolsRead(**/.env) and Read(**/secrets/**)Blocks built-in reads and applies to edits on the same path.
3 · Inspect tool callsPreToolUse hookRejects matching Read, Edit, Write, Bash, and PowerShell requests.
4 · Explain intentCLAUDE.mdUseful feedback for the model, but never the security boundary.

Hooks and command matching reduce accidental access. Isolation protects against bypasses and untrusted content.

Sources: https://code.claude.com/docs/en/permissions and /hooks-guide

Subagents

Subagent orchestration is a fan-out, fan-in contract

Main contextOwns the question and synthesisDefines scope, evidence, and the final decision.
InventoryRead-only repo topology and ownership
SecurityIAM and secret exposure review
VerificationTests, policy checks, and rollback evidence
Return schemaFinding · evidence · confidence · next check

Good orchestration limits tools, assigns non-overlapping work, and budgets the number of workers.

Source: https://code.claude.com/docs/en/sub-agents

Context engineering

Context split decision

Use a subagent
  • Search or logs would flood the main context
  • The task has a clear return value
  • Work can run independently
  • A narrower tool set reduces risk
Keep it in the main context
  • The next decision needs the full conversation
  • Steps are serial and share evolving state
  • Several workers would edit the same files
  • Coordination costs more than the work

A subagent saves main-window space, but it still consumes tokens and must receive enough context to succeed.

Long-running work

/goal and /loop solve different control problems

/goalWork until a condition is metAn evaluator checks the transcript after each turn. Use a measurable finish line, a proof command, constraints, and a turn or time bound./goal tests pass, lint is clean, no other files change, or stop after 12 turns
/loopWake up and check againA prompt reruns at a fixed or model-chosen interval while the session remains open. Use it for polling deployment or review state./loop 5m check the rollout; report only on change or failure

A goal pursues completion. A loop observes time-dependent state. Neither expands permissions.

Sources: https://code.claude.com/docs/en/goal and /scheduled-tasks

Model routing

Jev and Needle 3 trade generality for specialized execution

ClaudeOpen-ended reasoningRepository exploration, code changes, incident synthesis, and ambiguous planning.Cloud model · natural language and tools
Jev · TypeSafe AITyped probabilistic decisionsHigh-volume classification, routing, scoring, extraction, and guardrails that software consumes directly.Early access · vendor claims require validation
Needle 3 · CactusLocal tool calls and extractionOffline or private actions on mobile, edge, appliances, and constrained devices.8–29 MB binary is a vendor claim

Route by task shape, latency, deployment location, and failure handling. Keep a fallback for low confidence and unsupported work.

Sources: https://typesafe.ai/blog/introducing-system-one-models-and-jev and https://www.cactuscompute.com/needle

Cost, context, and effort

RTK, Caveman, and Ponytail remove different waste

$ rtk kubectl logs
failures and signal only

RTK

Filters terminal output before it enters model context.

Measure: input bytes and retained diagnostic signal

Caveman

Shortens prose while keeping commands, errors, and technical facts.

Measure: output tokens and missing facts

Ponytail

Pushes toward YAGNI, standard-library use, and the smallest correct diff.

Measure: changed lines and acceptance criteria
Sources: GitHub repositories for rtk-ai/rtk, JuliusBrussee/caveman, and DietrichGebert/ponytail.

2InvestigateScoped rules and read-only subagents
3PlanFiles, commands, risk, and rollback
4ChangeSmall diff with runtime guardrails
5VerifyFocused checks, broad checks, diff review

Next 30 days

Build one controlled path before scaling

Week 1Choose one benchmark taskStable input, measurable output, low blast radius.
Week 2Commit one rule and one skillReview ownership, triggers, evidence, and failure cases.
Week 3Add one hard guardrailSecret boundary, destructive-command block, or CI gate.
